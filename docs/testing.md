# Тестирование проекта

## Автоматические тесты

Автоматические тесты запускаются в изолированной PostgreSQL-базе, чтобы не изменять рабочие данные приложения.

Запуск:

```bash
sudo docker compose -f docker-compose.test.yml up --build --abort-on-container-exit --exit-code-from tests
```

Если Docker сообщает о старом конфликтующем тестовом контейнере, можно удалить только тестовые контейнеры без удаления volume:

```bash
sudo docker rm -f tihon_diplom_tests tihon_diplom_test_db
sudo docker network prune -f
```

Локальный запуск возможен только при наличии тестовой PostgreSQL-базы:

```bash
TEST_DATABASE_URL=postgresql+psycopg2://tihon_test:tihon_test@localhost:55432/tihon_diplom_test pytest
```

По умолчанию тесты не используют рабочую `DATABASE_URL`, если окружение не помечено как `APP_ENV=test`.

### RBAC и web smoke tests

Файл: `tests/test_rbac_web.py`

Проверяется:

- исполнитель не видит действие создания задачи на главной странице;
- исполнитель не видит действие создания задачи на странице задач;
- администратор видит действие создания задачи;
- исполнитель не может открыть страницу создания задачи;
- страница управления пользователями доступна только администратору;
- исполнитель не может открыть чужую задачу;
- исполнитель не может скачать вложение чужой задачи;
- в комментариях отображается ФИО автора;
- отключенный пользователь не может войти в систему.

### API задач

Файл: `tests/test_tasks_api.py`

Проверяется:

- администратор может создать задачу через API;
- исполнитель не может создать задачу через API;
- исполнитель может изменить статус своей задачи;
- исполнитель не может открыть чужую задачу через API;
- добавление комментария создает запись комментария и audit log.

### Zabbix webhook

Файл: `tests/test_zabbix_integration.py`

Проверяется:

- webhook принимает payload с лишними полями;
- альтернативные ключи Zabbix нормализуются в поля системы;
- создается задача-инцидент;
- исходный payload сохраняется;
- создается уведомление Rocket.Chat со статусом `skipped`, если интеграция отключена;
- повторный `event_id` не создает дубль задачи;
- webhook требует Bearer-токен;
- при отсутствии `event_id` генерируется стабильный служебный идентификатор.

### CSV-отчеты

Файл: `tests/test_reports.py`

Проверяется:

- экспорт задач доступен администратору и руководителю;
- экспорт задач недоступен исполнителю;
- экспорт инцидентов доступен руководителю;
- экспорт инцидентов недоступен исполнителю.

## Ручные проверки

Ручными остаются проверки, которые зависят от внешних сервисов или визуального качества интерфейса.

### Интерфейс

Проверяется вручную:

- читаемость главной страницы;
- читаемость списка задач;
- удобство фильтров;
- корректность карточки задачи;
- отображение кнопок для разных ролей;
- форма создания и редактирования задачи;
- форма управления пользователями.

### MinIO

Проверяется вручную:

- загрузка файла через браузер;
- скачивание файла через браузер;
- корректное имя скачиваемого файла;
- отсутствие необходимости прямого доступа браузера к MinIO.

### Rocket.Chat

Проверяется вручную при наличии реального Incoming Webhook:

- включить `ROCKETCHAT_ENABLED=true`;
- задать `ROCKETCHAT_WEBHOOK_URL`;
- создать Zabbix-инцидент;
- убедиться, что сообщение дошло в Rocket.Chat;
- проверить запись в `/notifications`.

### Zabbix

Полноценная проверка с реальным Zabbix проводится при наличии развернутого Zabbix-сервера. Для дипломного стенда допустима контрактная проверка webhook-запросом, потому что интеграция реализована как HTTP webhook-контракт.
